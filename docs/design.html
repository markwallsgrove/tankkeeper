Tankkeeper

Talk to Claude about your fish tank. Tankkeeper is a planned Home Assistant integration that holds the tank's plan, records and decisions, runs the reminders and checks the tank's status. It is MCP first: you set it up, change it and ask about it in a conversation with Claude, from Claude Code on your laptop or from Assist in Home Assistant. The panel is the fallback. It stays behind Tailscale.

HA Container 2026.11.2 MCP first No GitHub or 1Password at run time Anthropic API, outbound only

Summary

  • MCP first. Everything you can see or do in the panel, Claude can also see and do through its tools, in the same change. You set the tank up, edit it and ask about it in a conversation. The panel and dialogs are the fallback.
  • Talk to it any time, from two places: Claude Code or Claude Desktop on your laptop, over MCP, or Assist inside Home Assistant on the phone or the web.
  • Conversations are kept. Every conversation is stored with the changes it made. You can read past ones in the panel, and Claude reads them to remember what you discussed.
  • One integration, tankkeeper, replaces separate records, YAML packages and scripts. It stores everything in Home Assistant's own storage, which HA backups already include.
  • It owns its calendar. The integration creates a calendar.tankkeeper entity, so a calendar is always installed and events can be renamed Complete: or Skip:.
  • Rules check the tank all the time and set a status: On course, Watch or Act. A change of status sends a notification.
  • Talk to it three ways: the Home Assistant app on your phone, Home Assistant in a web browser, and Claude Code or Claude Desktop. All three go through the Tailscale URL.
  • It can run the light (optional). You tell it which lights the tank has. It owns their schedule and shows it on the dashboard.
  • You confirm every change. Claude records what you tell it straight away. Anything that changes doses, the plan, the light schedule, decisions or the tank's details, Claude reads back to you first, and it changes only when you say yes, in the conversation or in the panel.

The claude.ai app and website can't connect. claude.ai calls connectors from Anthropic's cloud, not from your device, so it can't reach a server that only Tailscale can reach (Anthropic support). On your phone and the web you talk to the tank through Home Assistant's Assist chat instead, which uses the Anthropic API. The only way to use claude.ai would be to expose Home Assistant to the internet, which this design rules out.

How it fits together

The integration is the only place that stores data. Assist and the MCP server call the same tools, so a dose recorded from your phone and one recorded from Claude Code end up in the same log.

Setting it up

Install once, give the tank a name, then talk it through with Claude. Claude asks about the tank, the water, the products, what's in the tank, the light and the reminders, and sets it all up. The step-by-step dialogs stay as a fallback. Everything can be changed later the same way.

  1. Install the code. scripts/deploy.sh copies custom_components/tankkeeper to Home Assistant's config/ folder. Home Assistant restarts once.
  2. Add the integration. Settings → Devices & services → Add integration → Tankkeeper. Give the tank a name and choose how to set it up: talk to Claude (Assist or Claude Code), or the step-by-step dialogs.
  3. Set up chat. Add Home Assistant's Anthropic integration with an API key, then pick it as Tankkeeper's agent. Optional: without it, the panel, reminders and rules still work.
  4. Connect Claude Code. Turn on Home Assistant's MCP Server integration and run one command on the Mac (shown further down).

How they're recorded

  • Assist: Tankkeeper registers its own conversation agent, which passes each message to the Anthropic integration's agent and stores every turn: your words, Claude's answer and each tool call.
  • Claude Code and Claude Desktop: the MCP server only sees tool calls, not the chat. Tankkeeper groups the tool calls by MCP session, and its instructions ask Claude to call save_conversation with a title, a summary and the key messages before it finishes. An optional Claude Code hook can send the full transcript.
  • Every record change points to the conversation that made it.

How Claude uses them

  • Before it answers, Claude can search past conversations for what you already said, for example "you said you'd watch for floating Riccia".
  • Reviews can look back over recent conversations and notice things you mentioned but never logged.
  • You can delete a conversation in the panel. Its changes stay in the history.
  • Conversations are kept in Home Assistant, for as long as you set (default: forever).

How a change gets made

The answers to decisions come from you. Claude records facts on its own. Anything else it reads back to you, and saves only when you say yes. You can say yes in the conversation or in the panel.

Claude does on its own

  • Record a dose, test or note
  • Complete or skip a task you said you did
  • Explain the status, plan and decisions
  • Add an open question or an assumption, marked as one
  • Propose a change
  • Save a conversation

Only after your yes

  • Accept a decision, or replace one
  • Change a dose, the plan or a threshold
  • Change the tank, water, products or contents
  • Change the light schedule
  • Change reminders and Claude settings
  • Remove records (kept in the history)
  • Undo an earlier change

Only you, in Home Assistant

  • Turn the light on or off by hand
  • Change the API key, or turn the tools off
  • Delete a conversation or wipe the history
  1. You ask in Assist or Claude Code, for example "plan a water change on Saturday".
  2. Claude calls propose_change with what changes, why, and which decision or test it rests on. It gets back the change and a one-use confirm code.
  3. Claude reads the change back to you in the conversation. It also shows in Waiting for you in the panel.
  4. You say yes. Claude calls apply_change with the code. Or you tap Accept in the panel, or reject it.
  5. The integration writes the change, updates the calendar, and keeps the old version with a link to the conversation. Undo puts it back.

The light (optional)

Without a light, the Light card, the light rule and get_light stay hidden. With one, the integration takes over the light schedule from today's automation. It knows which lights you have and how each is controlled, so Claude can work out a better schedule. Claude proposes it; you accept it, and you decide what's acceptable.

What you tell it

  • Each light: its entity, model, and how it's controlled: on/off, dimmable, or colour.
  • Its schedule: on and off times, and for a dimmable light the ramp and brightness.

Claude also reads the plant list (with each plant's light needs), the notes and the tests.

When Claude proposes a change

  • From what you report, for example algae, plants growing poorly, or new plants.
  • From a review after a test or a note.
  • When you ask, for example "keep the light on until 22:00 tonight".
  • You say yes in the conversation, or accept from the notification or the panel. Nothing changes until you do.

Camera (optional)

A small camera pointed at the front glass lets Claude look at the tank. Everything else works without it. You add it later from the integration's options.

What Claude can see

  • Water colour: yellow from the driftwood, green or cloudy
  • Algae on the glass, the plants or the stones
  • Plants yellowing, melting or floating loose (the Riccia)
  • Water level
  • Later, with fish: a fish that looks unwell

What it can't see

  • Ammonia, nitrite, nitrate or pH. The test kits stay.
  • Anything in the dark. Photos are taken only while the light is on.

Reflections, room light and the camera's colour balance can fool it. Photos at the same time each day, with the same light, make comparisons fair.

Reviews

A review runs when something happens, not at a fixed time. It tells you whether the tank is in a good state.

What starts a review

  • A test is recorded
  • A task is completed or skipped
  • The status changes
  • Later: a sensor event, such as temperature drift, water level, a pH probe, or a light or filter fault
  • Optional: a daily review at a set time
  • Optional: a camera photo check

What you get back

  • Always: the rules' result, for example "Watch: pH 6.8 is under 7.0". It runs in Home Assistant and costs nothing.
  • If turned on: a short comment from Claude on trends and context, using the tank's contents and products. It uses the API.
  • Plan changes from a review go to Waiting for you as proposals.
  • Events close together, such as several readings in one sitting, give one review. A daily cap limits Claude's comments, so a busy sensor can't run up API usage.

Security

  • Home Assistant stays reachable only through Tailscale. Nothing is exposed to the internet.
  • Every channel signs in with your Home Assistant account. The MCP server uses Home Assistant's own login.
  • The Anthropic API key lives in Home Assistant's config entry for the Anthropic integration. It is not in the repo or 1Password at run time.
  • With the camera on, each photo check sends one photo of the tank to Anthropic. Photos are stored in Home Assistant only.
  • Claude can't switch any device. The light schedule changes only after your yes.
  • Conversations are stored in Home Assistant only, and go into its backups. Treat a backup as private.
  • A confirm code keeps Claude from saving a change it never showed you. It can't stop an assistant that ignores its instructions, so every change can be undone and shows which conversation made it.
  • Only outbound HTTPS to the Anthropic API leaves your server. What goes out is the conversation plus the tank records Claude reads.
  • Data is backed up with Home Assistant's backups. An export to the repo can be added later.

Cost

  • Claude Code and Claude Desktop: your Pro plan. No extra cost.
  • Camera (optional): about £18 once, plus API usage for each photo check.
  • Assist chat and Claude's review comments: Anthropic API usage, paid per use. A comment after each test plus a few chats a week should be small, but I haven't worked out a figure. Check Anthropic's pricing before choosing a model.
  • Rules, reminders and the panel: run in Home Assistant. No cost.

Quality

  • Target: Platinum, the highest tier of Home Assistant's integration quality scale. Platinum needs every Bronze, Silver and Gold rule, plus strict typing, a fully async library and an injected web session. Home Assistant grades only core integrations, so for a custom integration this is our own target. Every rule is tracked in quality_scale.yaml. hassfest doesn't grade custom integrations, so a test checks that each rule is done or exempt with a reason, and the review checks the rest.
  • Typed: mypy in strict mode over all code and tests. No Any and no ignores without a written reason.
  • Tested: 100% line and branch coverage with pytest-homeassistant-custom-component, against a real Home Assistant core in the tests, with no mocks of our own code.
  • Property-based tests with Hegel (hegeltest, from the Hypothesis authors) for the parts with rules: dose maths, status rules, history and undo, confirm codes, schedules and conversation recording. Hegel for Python is in beta and may change, so its version is pinned.
  • Reviewed twice: every PR is reviewed by Claude and by Codex. Each finding is checked, fixed test first, and both reviews run again until they find nothing.
  • CI on every PR: Ruff, mypy, pytest with coverage, hassfest and the HACS action.

Build order

  1. Check the risky parts first: Claude Code signing in to HA's MCP server over the Tailscale URL, a custom LLM API showing up as MCP tools, the MCP session id reaching the tools (for grouping conversations), and a custom conversation agent calling the Anthropic API.
  2. Records, tools and conversations: storage, history and undo, with each record's tools and conversation recording from the start.
  3. Calendar and reminders: calendar.tankkeeper, the to-do list and Complete/Skip.
  4. Light (optional): lights, schedule, one-day changes and the on/off log. Dose reminders follow the light-on time.
  5. Rules and status: the status sensor and status notifications.
  6. Proposals and setup by conversation: confirm codes, Accept/Reject/Discuss, and setup mode over MCP.
  7. Panel (fallback): the dashboard, the tabs and the step-by-step setup dialogs.
  8. Assist agent and Claude's review comments: Tankkeeper's conversation agent, setup in Assist, and review comments.
  9. Camera (optional): photo checks, photo alerts, the Camera and Seen by the camera cards, and get_photo. First check that Home Assistant's AI task can send a camera photo to the Anthropic integration.

Each step comes with tests and goes through its own PR.

Open questions
